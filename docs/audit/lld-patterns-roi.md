# LLD patterns audit — ROI-ranked findings

> Generated by LLD patterns audit (umbrella plan). Read-only audit; no code changed.

Low-level design = SOLID, dependency inversion, layering, SRP, and established design patterns (facade, adapter, strategy).

  1. Domain layer is persistence-aware (GORM tags in `domain/`)
  2. Git persistence bypasses store facade/internal pattern

## Findings (ranked)

### 1. Domain layer is persistence-aware — ROI 10/10 (High)

- **Location:** `pkgs/tasks/domain/models.go` (~418 lines — **Red** >350), `domain/app_settings.go`, `domain/git.go`; mappers in `store/model/map_*.go`
- **Issue:** Domain types carry `gorm:` tags, `gorm.io/datatypes`, and `TableName()` — persistence metadata lives with business types. Violates inward dependency direction.
- **Proposed change:** **Entity/persistence model separation** — pure domain types in `domain/`; GORM structs only in `store/model/` with existing mappers.
- **Effort / risk / blast radius:** 3–5 days; high risk (schema ripple); entire tasks domain, store, handlers, harness, web parsers.
- **Evidence:** Split is half-done via `map_*` files; domain still imports GORM types.

### 2. Git persistence bypasses facade/internal pattern — ROI 9/10 (High)

- **Location:** 10× `store_git_*.go`, `reconcile_git.go` (~586 lines — **Red** >500); no `internal/git/`; contrast `facade_tasks.go` → `internal/tasks/`
- **Issue:** Git is the only major store concern without facade/internal split. `reconcile_git.go` mixes DB transactions, `os.Stat`, and `gitwork.Service`.
- **Proposed change:** **Facade + internal subpackage** — `internal/git/` with reconcile phased into path resolution, worktree sync, branch bind collaborators.
- **Effort / risk / blast radius:** 3–4 days; medium–high risk; git handlers, store tests, reconcile tests.
- **Evidence:** `store/README.md` documents facade pattern; git is explicit exception.

### 3. Monolithic route registry in `handler.go` — ROI 8/10 (High)

- **Location:** `pkgs/tasks/handler/handler.go` L82–196 (~100 routes inline)
- **Issue:** SRP violation at wiring layer; git alone ~35 routes; every new resource touches same file; merge conflicts scale with API surface.
- **Proposed change:** **Resource-scoped route registration** — `registerTaskRoutes(m, h)`, `registerGitRoutes(m, h)`, etc.
- **Effort / risk / blast radius:** 4–6 hours; low risk; handler package only.
- **Evidence:** Single `NewHandler` registers all routes; no per-resource registration files.

### 4. Handler depends on concrete `*store.Store` — ROI 8/10 (High)

- **Location:** `handler/handler.go` struct; ~100+ `h.store.*` call sites across `handler_*.go`
- **Issue:** No handler-local interface; tests rely on real SQLite or full server harness. Harness already has `contract.Store` — asymmetric DIP.
- **Proposed change:** **Interface segregation / dependency inversion** — per-area interfaces or extend harness contract for HTTP layer.
- **Effort / risk / blast radius:** Multi-PR incremental; medium risk; all handlers, taskapi, tests. See [abstractions-roi.md](./abstractions-roi.md) #2.
- **Evidence:** `pkgs/agents/harness/internal/contract/store.go` + `store_assert_test.go`.

### 5. `TaskCycleDetailPage.tsx` is a god page — ROI 8/10 (High)

- **Location:** `web/src/tasks/pages/TaskCycleDetailPage.tsx` (~1,075 lines, 25+ functions)
- **Issue:** Page owns entire attempt-detail UX: state hook, phase rail, stream/audit panels, formatters, live tail. **Red** bar: route pages >150 lines (~7× over).
- **Proposed change:** **Container/presentational split** — move sections to `tasks/components/task-detail/attempt/`; page becomes wiring only (≤80 lines).
- **Effort / risk / blast radius:** 2–3 days; medium risk (UI regression); cycle detail tests.
- **Evidence:** Partial attempt helpers exist under `pages/attempt/` but most logic remains in page file.

### 6. Git I/O orchestration lives inside the store — ROI 7/10 (Medium)

- **Location:** `reconcile_git.go`, `store_git_global.go`, `handler_git_global.go`, `handler_git_helpers.go`
- **Issue:** Store methods accept `gitwork.Service` and perform git mutations inside DB transactions. Handlers also hold git service — dual ownership complicates rollback semantics.
- **Proposed change:** **Application service / orchestrator** (`pkgs/tasks/service/git_service.go`) composing `gitwork.Service` + store facade; store stays SQL-only.
- **Effort / risk / blast radius:** 3–4 days; medium–high risk; git vertical end-to-end.
- **Evidence:** Handler passes `h.gitService()` into store on every git mutator call.

### 7. No application service layer for multi-step HTTP flows — ROI 7/10 (Medium)

- **Location:** `handler_task_create_compose.go`, `handler_bootstrap.go`, `handler_tasks_retry.go`; zero `pkgs/*/service/` packages
- **Issue:** Handlers mix transport (HTTP status, decode, trace) with use-case logic — hard to reuse from worker/harness without duplicating.
- **Proposed change:** **Application service / use-case layer** between handler and store (HTTP-agnostic orchestration).
- **Effort / risk / blast radius:** Multi-PR; medium risk; create, bootstrap, retry flows.
- **Evidence:** Harness has orchestration pattern; HTTP layer does not.

### 8. `TaskCreateModal.tsx` god component — ROI 7/10 (Medium)

- **Location:** `web/src/tasks/components/task-create-modal/TaskCreateModal.tsx` (~826 lines)
- **Issue:** Form state, mutations, draft flow, template fields, scenarios popover, footer actions in one component. **Red** bar: presentational >250 lines.
- **Proposed change:** **Smart container + dumb sections** — extend existing `TaskCreateModal*` field/footer splits; modal shell ≤120 lines.
- **Effort / risk / blast radius:** 2 days; medium risk; create modal tests.
- **Evidence:** Field components exist but orchestrator remains monolithic.

### 9. Handler contract-test sprawl — ROI 6/10 (Medium)

- **Location:** 23× `handler_http_*_contract_test.go`; several **Red** (>600 lines): checklist (660), settings (593), cycles (579)
- **Issue:** Inverted test pyramid — large whitebox contract tests in handler package; README prefers `internal/handlertest` black-box tests.
- **Proposed change:** **Test pyramid + shared contract fixtures** — table-driven suite in `internal/handlertest`; handler tests only for unexported helpers/SSE internals.
- **Effort / risk / blast radius:** Multi-PR; low–medium risk; handler test suite.
- **Evidence:** Parallel non-contract `handler_http_*_test.go` files duplicate coverage.

### 10. `types/task.ts` monolithic shared type bag — ROI 6/10 (Medium)

- **Location:** `web/src/types/task.ts` (~480 lines — at **Red** threshold >400)
- **Issue:** Mixes wire DTOs, UI enums, draft/template shapes, list params, compose payloads.
- **Proposed change:** **Bounded context type modules** aligned with `parseTaskApi*.ts` — `taskCore.ts`, `taskDrafts.ts`, `taskTemplates.ts`.
- **Effort / risk / blast radius:** 1–2 days; medium risk (import churn); types consumers across web.
- **Evidence:** Parser split already exists in API layer; types lag behind.

### 11. `TaskDetailPage.tsx` mixes page, mutations, render tree — ROI 6/10 (Medium)

- **Location:** `web/src/tasks/pages/TaskDetailPage.tsx` (~571 lines)
- **Issue:** Inline mutation hooks and ~300-line `renderTaskDetailLoadedView`. **Red** bar: route page >150 lines.
- **Proposed change:** Extract mutations to `tasks/hooks/useTaskDetail*.ts`; loaded view to `TaskDetailLoadedView.tsx`; page ≤80 lines.
- **Effort / risk / blast radius:** 1–2 days; medium risk; task detail tests.
- **Evidence:** Mutations and rendering interleaved in single page file.

### 12. `web/src/api/repo.ts` bypasses shared fetch adapter — ROI 5/10 (Low)

- **Location:** `web/src/api/repo.ts` vs `web/src/api/shared.ts`
- **Issue:** Repo endpoints use raw `fetch()` instead of centralized `apiFetch` with timeout, error parsing, UI test interceptor.
- **Proposed change:** **Adapter pattern** — route all HTTP through `shared.ts` helpers; repo module keeps query builders only.
- **Effort / risk / blast radius:** 2–3 hours; low risk; repo/diff/health clients.
- **Evidence:** Inconsistent timeout/abort/error behavior vs other API modules.

## Boundary check summary

| Check | Result |
| --- | --- |
| Handler importing DB drivers | Clean |
| Domain importing HTTP | Clean |
| Domain importing ORM | **Fail** — GORM in domain |
| Web cross-feature deep imports | Mostly clean — `@/tasks` barrel from `app/` |
| Web `fetch` outside `api/` | Minor leak — `repo.ts` |
| Route registration density | High — ~100 routes in one constructor |
| Test pyramid | Bottom-heavy — many large handler contract tests |

## Suggested refactor sequence

1. Domain/persistence split (#1) — unlocks clean store and service layers
2. Git → facade/internal + service (#2, #6) — highest backend complexity
3. Route registration extraction (#3) — low risk, immediate reviewability
4. Handler store interfaces (#4) — pairs with service layer (#7)
5. Web god-file splits (#5, #8, #11) — parallel UI-only PRs
6. Test consolidation (#9) — after handler/service boundaries stabilize
