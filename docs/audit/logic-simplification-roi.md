## Findings (ranked)

### 1. Reconcile worktree row matching — triple skip paths — ROI 9/10 (High)

- **Location:** `pkgs/tasks/store/reconcile_git.go` L169–252
- **Issue:** Non-main row loop uses `matched` flag plus three separate blocks appending `WorktreesSkipped{Reason: "path_and_branch_not_found"}` for overlapping failure cases.
- **Proposed change:** Extract `resolveLiveWorktree(row, liveByPath, liveByBranch, branchByID, dbRows) (*gitwork.Worktree, *ReconcileSkippedWorktree)` with single return path per failure reason; main loop becomes match → skip → path update.
- **Effort / risk / blast radius:** 4–6 hours; medium risk (git reconcile correctness); `reconcile_git_test.go` must stay green.
- **Evidence:** Three append-skip blocks at L196–211, L220–226, L230–240 with same reason string.

### 2. Checklist mutations — three optimistic pipelines — ROI 9/10 (High)

- **Location:** `web/src/tasks/checklist/hooks/useTaskDetailChecklist.ts` L135–332
- **Issue:** `buildAddChecklistMutationOptions`, `buildUpdateChecklistTextMutationOptions`, `buildDeleteChecklistMutationOptions` each repeat: `beginGuardedTaskWrite` → cancel → snapshot → optimistic patch → error restore → invalidate → `endGuardedTaskWrite`.
- **Proposed change:** `buildGuardedChecklistMutation({ rumKind, applyOptimistic, shouldRestore, ... })` factory; add/update/delete supply only `applyOptimistic` + `mutationFn` + toast copy.
- **Effort / risk / blast radius:** 4–6 hours; medium risk (optimistic UI + mutation guard); checklist tests.
- **Evidence:** ~200 lines of structurally identical mutation option builders.

### 3. Cycle handler pagination — duplicated limit+1 cursor — ROI 9/10 (High)

- **Location:** `pkgs/tasks/handler/handler_cycles.go` L68–91 and L147–171
- **Issue:** Identical `hasMore` / trim / map / optional next-cursor logic in `getTaskCycles` and `getTaskCycleStream` (noted in `handler_cycles_json.go` L103–104).
- **Proposed change:** Generic `paginateRows[T,R](rows, limit, mapFn, nextCursor)` helper; both handlers call it with domain-specific mappers.
- **Effort / risk / blast radius:** 2–3 hours; low risk; cycle contract tests.
- **Evidence:** Byte-for-byte parallel pagination blocks in two handlers.

### 4. Task create modal footer — identical edit branches — ROI 9/10 (High)

- **Location:** `web/src/tasks/components/task-create-modal/TaskCreateModal.tsx` L654–671
- **Issue:** Two separate `if` branches return identical `<TaskCreateModalEditFooterActions />` for `isTaskEdit` and `isTemplateMode && isEdit`.
- **Proposed change:** Collapse to `if (presentation.isEdit) { return <TaskCreateModalEditFooterActions ... /> }` — `isEdit` already covers both at L115.
- **Effort / risk / blast radius:** 15 minutes; low risk; create modal tests.
- **Evidence:** Duplicate JSX with same props in consecutive branches.

### 5. Task create modal presentation — nested ternary matrix — ROI 8/10 (High)

- **Location:** `TaskCreateModal.tsx` L102–164 (`modalTitle`, `modalTitleId`, `idsPrefix`, `modalBusy`)
- **Issue:** Four independent 3-way ternary chains keyed on `(isTaskEdit, isTemplateMode, composeOperation)`.
- **Proposed change:** Derive `mode` enum (`task-edit` | `template-edit` | `template-create` | `task-create`) and lookup `PRESETS[mode]` object.
- **Effort / risk / blast radius:** 1–2 hours; low risk; modal a11y ids must stay stable.
- **Evidence:** Four parallel ternary chains for related presentation fields.

### 6. SettingsSelect — duplicate list/search keyboard handlers — ROI 8/10 (High)

- **Location:** `web/src/settings/SettingsSelect.tsx` L289–328
- **Issue:** `createSearchKeyDownHandler` and `createListKeyDownHandler` are byte-for-byte identical (Escape, ArrowDown, ArrowUp, Enter).
- **Proposed change:** Single `onMenuKeyDown` callback passed to search input and list; memoize `createTriggerKeyDownHandler` (L571–578) currently recreated every render.
- **Effort / risk / blast radius:** 2–3 hours; medium risk (a11y keyboard nav); settings tests.
- **Evidence:** Identical handler bodies in two factory functions.

### 7. Reconcile `AllowRemove` — two delete paths, same guards — ROI 8/10 (High)

- **Location:** `pkgs/tasks/store/reconcile_git.go` L292–346
- **Issue:** Two branches (no `BranchID` vs unmatched non-main) both call `hasAnyTaskOnWorktree`, append `"has_task_ref"`, then delete — with redundant O(n) `stillLive` scan in second path.
- **Proposed change:** `shouldRemove(row)` predicate consolidating guards; single delete path; replace `stillLive` loop with `liveByPath` lookup (see finding #8).
- **Effort / risk / blast radius:** 3–4 hours; medium risk; reconcile tests.
- **Evidence:** Duplicated guard + delete logic in two branches.

### 8. Reconcile remove loop — redundant `stillLive` scan — ROI 8/10 (High)

- **Location:** `pkgs/tasks/store/reconcile_git.go` L321–327
- **Issue:** After checking `matchedLive` and `matchedRowIDs`, loops all live worktrees to see if path exists — but `liveByPath` was built at L166.
- **Proposed change:** Replace loop with `_, stillLive := liveByPath[worktreePathKey(row.Path)]`.
- **Effort / risk / blast radius:** 30 minutes; low risk; reconcile tests.
- **Evidence:** O(n) scan when O(1) map lookup available.

### 9. `getTaskCycle` — duplicate ownership validation — ROI 8/10 (High)

- **Location:** `handler_cycles.go` L106–114 vs `handler_cycles_query.go` L48–57
- **Issue:** `getTaskCycle` manually compares `cycle.TaskID != taskID`; other handlers use `assertCycleBelongsToTask` — two code paths for same logic.
- **Proposed change:** Use `assertCycleBelongsToTask` in `getTaskCycle` before or after fetch; eliminates divergent 404 behavior risk.
- **Effort / risk / blast radius:** 30 minutes; low risk; cycle contract tests.
- **Evidence:** `assertCycleBelongsToTask` used in stream, verdicts, patch, phase handlers but not get.

### 10. Task cycle detail page — duplicated phase-filter empty states — ROI 8/10 (High)

- **Location:** `web/src/tasks/pages/TaskCycleDetailPage.tsx` L690–712 (`CursorActivityPanel`) and L789–804 (`AuditActivityPanel`)
- **Issue:** Same branching: filtered empty state with "Show all phases" vs generic empty message.
- **Proposed change:** `PhaseFilteredEmpty({ filterLabel, kind, onClear })` shared component with kind-specific default copy.
- **Effort / risk / blast radius:** 1–2 hours; low risk; cycle detail page tests.
- **Evidence:** Parallel empty-state JSX in two panel components.

### 11. Harness `processState` — boolean/field soup — ROI 7/10 (Medium)

- **Location:** `pkgs/agents/harness/cycle.go` L28–81; writes in `cycle_loop.go` L249–255
- **Issue:** 20+ flat fields mixing verify, git, resume, reporting; `continuation` / `resumeNotice` / `interruptedPhase` duplicated from `cycleLoopOpts` into `processState`.
- **Proposed change:** Group into nested structs: `cycleLifecycle`, `phaseLifecycle`, `verifyState`, `gitState`, `resumeMirror` — no new abstraction layer, just field grouping.
- **Effort / risk / blast radius:** 4–6 hours; medium risk (harness behavior); harness test suite.
- **Evidence:** Flat struct touched across `completeExecutePhase`, `terminateCycle`, recovery paths.

### 12. Harness timeout handling — dead helper vs inline duplicate — ROI 8/10 (High)

- **Location:** `pkgs/agents/harness/cycle.go` L210–214 (`invokeRunnerWithDecision`) vs L302–309 (`withOptionalRunTimeout`)
- **Issue:** `invokeRunnerWithDecision` inlines `context.WithTimeout` when `RunTimeout > 0`. `withOptionalRunTimeout` has same contract but is **never called** (grep confirms definition only).
- **Proposed change:** Use helper in `invokeRunnerWithDecision` or delete unused `withOptionalRunTimeout` if `WithCancelCause` path is intentional.
- **Effort / risk / blast radius:** 30 minutes; low risk; harness runner timeout tests.
- **Evidence:** `withOptionalRunTimeout` appears only at definition site in repo.
